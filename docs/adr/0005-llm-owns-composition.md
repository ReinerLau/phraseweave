# 大模型判断短语合并，脚本生成组合

## 状态

已由 [ADR 0007](0007-dependency-slot-closure.md) 取代

## 背景

组合规则需要语言判断，但直接让模型自由输出所有英文范围容易漏掉自然的中间步骤，也难以稳定排序。脚本仍应负责可确定的范围构造和渐进顺序。

## 决策

1. 脚本负责分句、token 化、OEWN/Morphy 匹配、句法回退和实义核心判断。
2. 分析 JSON 只保存原句和 `atoms`，不保存 `learning_units` 或组合基线。
3. 大模型按从右向左的顺序，对每个左侧核心判断它能否自然并入当前右侧短语；每个间隙返回一个布尔合并标记。
4. model-plan 使用 schema 2 保存合并标记、按输出顺序排列的中文提示和整句翻译，不再让模型指定组合范围或组合类型。
5. 脚本按标记构造原文连续范围和右向左的渐进步骤；渲染器校验标记数量与类型、提示对齐和完整原句位置。
6. `--render-analysis` 保留为 core-only 兼容模式，只渲染脚本识别的核心和完整原句。

## 后果

- 局部合并判断由模型负责，合并范围和渐进顺序由脚本确定；
- 分析 JSON 更小，且不会把脚本组合误当成模型决策；
- 组合规则不再属于固定规则文件；
- 模型计划不能表达任意非渐进组合，回归测试覆盖右向左合并和并列边界。

## 兼容性

分析 schema 从 6 升级到 7；model-plan schema 从 1 升级到 2。旧分析文件不自动迁移，需要重新运行分析步骤；`--render-analysis` CLI 保留，但只接受 schema 7 并执行核心-only 渲染。
