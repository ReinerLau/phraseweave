# 后序遍历与显式方向的依存槽位

## 状态

已由 [ADR 0012](0012-adjacent-subtree-closure.md) 取代。此前取代 [ADR 0008](0008-node-local-dependency-paths.md)；结果顺序由 [ADR 0010](0010-prerequisite-learning-unit-order.md) 修订；多方向匹配语义由 [ADR 0011](0011-bidirectional-slot-priority.md) 修订。

## 背景

学习单元应由依存树中可检查的关系和人工维护规则直接确定。节点按后序顺序处理；每条规则从自己的锚点查找目标节点，不能让一个节点生成的短语成为其他节点的输入。

## 决策

1. 执行器严格按依存树后序遍历处理节点：先处理所有子节点，再处理当前节点。遍历顺序不限制槽位查找方向。
2. 每条规则最多配置一个必需槽位和一个可选槽位。槽位可从锚点或此前命中的节点出发，沿 `head`、`child` 或两个方向查找。
3. 槽位的 POS 和 dep 条件分别可选，均针对查找到的目标节点；未配置的条件不参与匹配。配置了两个条件时，目标节点必须同时满足。
4. 当前词对阶段只匹配必需槽位；必需槽位为空时，锚点本身成为单元。可选槽位保留给后续短语组合，不参与当前阶段。不同锚点独立生成单元；相同 token 集合去重并合并规则标签，完整原句最后追加。
5. 锚点条件相同且槽位路径可配置多方向时，使用一条规则表达多个方向。例如 ADP `prep` 锚点沿 `head` 或 `child` 方向找到满足条件的名词性目标，都由 U7 处理。
6. 当前规则只依据 POS 和依存标签，不使用词元条件。
7. 规则 schema 升为 8；旧规则文件及其计划摘要失效，必须重新生成计划。

## 后果

- `Tulane` 可沿 `head` 方向找到 `University`，生成 `Tulane University`。
- ADP `prep` 规则可沿两个方向匹配目标节点，例如生成 `light on`、`with light` 和 `for you`。
- 多方向槽位会为每个符合目标条件的节点分别生成组合；不要求所有方向同时命中。
- U7 仅依靠 POS 和 dep 条件区分介词组合；因此 `of light` 这类依存关系符合条件时也会生成。
- 后序执行产生初始顺序；最终结果按 [ADR 0010](0010-prerequisite-learning-unit-order.md) 排列，完整原句始终为最后一个单元。
