# 由依存槽位闭合生成渐进学习单元

## 状态

已由 [ADR 0008](0008-node-local-dependency-paths.md) 取代，保留作历史背景。它此前取代了 [ADR 0006](0006-spacy-dependency-learning-units.md)。

## 背景

直接把 spaCy 依存子树投影为连续短语，会将 `of light` 这样的关系成分错误地视为完整子树；按相邻词或共享词扩展也会组合缺少构式依据的片段。共享依存边只能说明句法关系，不能单独说明一个节点需要什么成分才能闭合。

## 决策

1. 固定版本的 spaCy 只提供分句、词性、依存关系、形态和词位；由 JSON 规则表声明节点的闭合类别、必需槽位和可选依存扩展。
2. 引擎自底向上为每个节点生成所有满足必需槽位的闭合版本，再通过已配置的可选边枚举扩展。槽位来源可以是闭合子单元，也可以是规则允许直接吸收的原始 token。
3. `closed` 是规则状态，不是自然度判断。介词规则若要求 `pobj/pcomp`，`of light` 和 `from University` 都是闭合单元；`of`、`kind of`、`Sleeping with` 因介词对象槽未填而不输出。
4. 可选依存分支可以省略，因此允许生成非连续学习单元。schema 2 的 `segments` 记录所选原文字符区间，呈现文本按原文顺序拼接并以一个空格连接区间。
5. 只尝试已配置的直接依存边。无匹配规则的结构不触发通用回退，并记录在可选追踪报告中；单节点状态超过规则表上限时明确失败，不截断结果。
6. 同一来源 token 集合只输出一次。按依存树后序遍历节点，节点内按闭合扩展深度排序；完整原句始终作为最后一个单元。
7. 渲染校验重新运行固定 spaCy 和同一规则表，比较计划、来源片段和规则摘要。中文提示数组与所有单元逐项对齐；PhraseWeave 导入 schema 1 保持不变。

## 后果

- 必需/可选槽位、节点类别及特征转换可由用户在 JSON 规则表中维护，不需要改变引擎遍历方向。
- 可以生成诸如 `from University` 的跳词片段，并能用多个原文区间验证其来源。
- 规则覆盖范围决定输出覆盖率；未覆盖结构会出现在追踪报告中。
- 英文计划 schema 由 1 升级到 2，旧计划需要重新生成。

## 初始覆盖

初始规则覆盖名词、专名、代词、形容词、副词、有限与非限定动词、介词宾语、限定词、所有格、名词修饰语、介词扩展、系词补语、情态助动词和主语槽位。新增语言现象通过扩展规则表处理。
