# 由大模型编排渐进学习单元组合

## 状态

已接受

## 背景

仅依靠实义核心和固定的右向组合规则，容易生成表面连续但不适合独立学习的片段。例如：

```text
light on could be bad
```

原句中的自然表达其实依赖完整框架：

```text
Sleeping with a light on
```

这类语境绑定构式无法通过少量固定词法规则完整覆盖。

## 决策

采用混合流程：

1. 脚本使用固定 OEWN、Morphy、spaCy 和版本化规则识别实义核心。
2. 脚本生成确定性组合基线，作为模型输入而不是最终英文结果。
3. 大模型结合原句语境决定核心如何组合，可以删除不自然的组合、扩展语境绑定构式或增加新的连续原文片段。
4. 大模型只能返回原句字符范围和构式类别，不能自由改写英文。
5. 脚本验证字符范围、核心覆盖、单元顺序、提示对齐和完整原句位置后再渲染。
6. 验证失败时自动修复一次；仍失败则不生成残缺报告。

模型计划与旧的分析 JSON 分离。旧 schema 6 和确定性渲染继续可用，混合模式使用独立的 model-plan schema 1。

## 构式范围

构式类别不是预先穷举的完整英语语法，而是用于输出和回归测试的有限分类，例如：

- `state_frame`：`with a light on`
- `phrasal_verb`：`turn on`
- `verb_frame`：`be able to`
- `prepositional_frame`：`one of`
- `clause_frame`：`suggest that...`

模型可以发现新的连续片段，但必须保留至少一个脚本确认的实义核心。

## 后果

优点：

- 可以处理依赖上下文的自然构式；
- 不需要为每个句式建立单独硬编码规则；
- 保留原文复现和导入格式的稳定性。

代价：

- 英文组合不再完全由确定性脚本决定；
- 需要固定 model-plan schema 和模型提示词；
- 需要通过回归样本监控模型行为变化；
- 混合模式具有模型调用的延迟和失败可能。

## 不采用的方案

不把所有功能词提升为实义核心，也不把每个相邻实义词自动拼接。这样会产生大量没有语境意义的中间单元，并且无法区分 `light on` 与 `with a light on`。
